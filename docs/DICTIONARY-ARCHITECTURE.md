# 词库下一阶段方案：参考水杉输入法

研究日期：2026-10-12（Asia/Shanghai）。本文件是独立实现设计及来源核对记录，不代表现有引擎已完成数据库或语言模型升级。

## 当前词伴的实查结果

两版当前共享的内置数据共7194条：6831条单字读音、363条多字词或短语；英语、日语、西班牙语各130条非空释义。记录条数不是不同汉字数，也不是拥有译文的词数。Unicode基础单字解决部分编码召回，不等于成熟常用词库。常用词补充包的1800是编辑默认权重，不是从真实语料统计出的词频。

`core/lexi.cpp`当前仍逐条匹配，整句用词频启发式分词拼接；没有上下文语言模型。文件上限8MiB、全局合计上限50000条。扩大词库不能仅改大此上限：先加索引、覆盖率测试和规模基准。自定义词库仍是8列UTF-8 TSV，现有个人置顶/隐藏、词频与同步行为须保留。

## 已核验的参考事实

1. 水杉以文本维护源词库，以构建过程生成查询数据库；输入词条和候选译词分工不同，不能把拼音词典当作三语翻译词典。[词库源数据说明](https://github.com/metasequoiaime/msime-dictionary/blob/4909582a8ce345c23809750e675e3d9e5f9516df/README.md)。
2. 所查Windows引擎用SQLite检索。英文词条有前缀范围查询，释义另行按源词查询；全拼契约规定分桶格式。此处只分析职责，不移植它的实现。[英文查询](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/engine/english/english_dictionary.cpp)、[格式契约](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/engine/contracts/dictionary/format.json)。
3. Windows分支的词格整句排序另用KenLM三元模型`sc.lm`，由锁定的ARPA转换并校验输入与输出摘要；它不由该分支词库发布包直接携带。[模型说明](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/language-model/README.md)、[模型锁](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/language-model/lock.json)。
4. 用户词典状态支持一致性导出、在新目录准备、空闲时切换以及保留旧版本。这是可借鉴的数据更新方法，不是词伴现有同步已经具备的功能。[状态接口](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/engine/docs/dictionary-state.md)。
5. 可选专业包将中文输入、英文输入和释义分文件维护，校验读音与重复词并要求人工核对。[专业包说明](https://github.com/metasequoiaime/msime-dictionary/blob/4909582a8ce345c23809750e675e3d9e5f9516df/packs/README.md)。
6. 词库按上游分别声明许可，来源未明的数据有发布排除规则；不能从Windows仓库的GPL标签推断所有词库都是同一种许可。[逐项来源与许可](https://github.com/metasequoiaime/msime-dictionary/blob/4909582a8ce345c23809750e675e3d9e5f9516df/NOTICE.md)。

## 词伴的独立实现设计

下述均为本项目建议，尚未接入生产引擎。

| 层 | 内容 | 建议的存储与职责 |
|---|---|---|
| 基础输入词库 | 单字、常用词、多音字读法、拼音/简拼/五笔编码、基础词频 | 发布成只读SQLite包；用编码索引及内存前缀索引召回；手工默认权重与语料频率分别标注 |
| 多语言释义 | 汉字词义对应的英语、日语、西语短释义、词性、领域与审核状态 | 独立释义表；扩充某种语言不要求重写全部输入码表；无可靠释义时保持为空 |
| 个人词典 | 明确添加的词、用户译词修改、编码规则、置顶/隐藏、学习次数 | 独立可写库，叠加基础候选；升级基础包不覆盖它，仍遵守现有词频隐私范围 |
| 专业词包 | 软件、网规、旅行等领域的词与三语释义 | 用户按需启用；包内标明来源、许可、版本、语言覆盖率，可禁用与撤回 |
| 整句排序 | 多种分词路径、上下文搭配、语境下的多音字 | 后续独立加入二/三元统计模型和受限搜索；模型缺失时保留现有离线回退，不自动调用个人API |

拟定的词包对象不是他人的数据库结构：

- `entries`：词条稳定ID、显示词、源语言、词义/领域标识。
- `encodings`：词条ID、方案、规范化编码、音节序列、读音来源、基础权重；同词允许多个合法读音。
- `glosses`：词条ID、目标语言、短释义、可选解释、词性、审核状态、来源ID。机器生成和人工确认须区分；不将一条多义词翻译覆盖所有语境。
- `sources`：作者/上游、固定提交或版本、URL、适用许可、署名要求、文件摘要、允许进入哪些发行包及审核结论。
- `manifest`：包ID、schema版本、数据版本、编码方案、各语言覆盖数、资产摘要、构建工具版本和兼容引擎版本。

每个编码方案建立`(scheme, normalized_code)`索引，词条与读音组合去重。用户置顶保持优先；用户学习与基础权重分开存储，跨方案保留已有习惯。不同数据源、拼音与五笔的权重量级须归一化，不能把其他词库的数字原样当作本项目排序分数。

输入码表可以缺译文，学习词包则报告审核后的译词覆盖率。汉字输入词典、日文输入词典和中译日释义不是同一种资源。英文词典的中文解释也不能机械反向为“精准汉英翻译”：候选词性、语境和多义项需要另行校对。[ECDICT原项目说明](https://github.com/skywind3000/ECDICT)声明MIT并提供英译中字段，可作为后续评估线索；本轮未将其数据或代码引入项目。

## 构建和更新

1. 从逐项审核的上游取得固定版本，保存原始文件与许可；不在用户每次打字时联网下载。
2. 原创转换器校验编码、拼音音节边界、词与读音组合、权重边界、重复项、不可见字符和词义关联，输出变更与覆盖率报告。格式兼容不代表已取得再分发许可。
3. 建立SQLite包与查询索引，生成manifest与SHA-256，再做完整性及回读校验；基础包和模型分别版本化。
4. 在非活动目录准备新包，等待输入会话空闲后切换，成功前保留旧包；校验失败继续用旧包。
5. 个人同步仍默认关闭。按既有授权，仅交换自定义词库与常用语；不因为参考项目能同步更多状态就把词频、原始按键、整句、API密钥或录音加入同步。

## 来源选择与实施顺序

两版继续独立实现；当前私有版本保留闭源方向，公开版本保留现有原创部分MIT方向。GPL标注或来源未确认的数据暂不直接内置，不为了省事将混合大词库重新标为MIT。宽松许可的数据也需逐文件记录来源、归属、署名和衍生要求。这是本项目的数据选用边界，不是对所有闭源软件与数据组合的法律判断。

实施顺序建议：先扩充具有明确分发依据的常用词与人工核对译词，建立独立词包构建/校验；然后做查询索引与新旧词库兼容适配；再增加可查询、编辑、导入预览和回滚的词库管理；最后接入独立整句模型。不能把扩大单字数量或AI批量生成释义当作这些工作已完成。

验收拟采用5万、10万、50万条的规模样本，分别测冷启动、内存、输入查询P50/P95、整句首选准确率及译词覆盖率；真实词库和合成性能样本分开报告。修复、重启、银行、音乐、长句等测试应覆盖正常读音、歧义切分、简拼、纠错、候选翻页及个人词优先。两平台实际打字、两版本实际启用仍各自验收。
